The problem

Managed Linux boxes — corporate laptops, hardened servers, anything you don't have sudo on — still leave you wanting a real package manager for dev tooling. The official Homebrew installer wants root (it writes to /home/linuxbrew/.linuxbrew by default and calls sudo along the way). That's a non-starter on a locked-down host. The good news: Homebrew is just files. You can put the whole thing anywhere your user can write.

Installing into your own prefix

No root, no installer script — just clone it: 

mkdir -p ~/.linuxbrew
git clone https://github.com/Homebrew/brew ~/.linuxbrew/Homebrew
mkdir -p ~/.linuxbrew/bin
ln -s ~/.linuxbrew/Homebrew/bin/brew ~/.linuxbrew/bin/brew

That's the entire install. Nothing touched outside your home directory.

Wiring up the environment

Homebrew ships a helper that prints the exact environment it needs — don't hand-roll this: 

~/.linuxbrew/bin/brew shellenv

It sets more than just PATH: MANPATH, INFOPATH, HOMEBREW_PREFIX, HOMEBREW_CELLAR, HOMEBREW_REPOSITORY. Eval it in your shell and persist it: 

echo 'eval "$(~/.linuxbrew/bin/brew shellenv)"' >> ~/.bashrc
source ~/.bashrc

(~/.profile or ~/.zshrc instead, depending on your shell — the point is: whichever file actually gets sourced for your login shell on that host.)

Verify: 

which brew
brew --prefix
# ~/.linuxbrew

The catch: no bundled toolchain

On macOS, Homebrew formulae mostly ship as bottles (prebuilt binaries). On Linux, plenty still need to compile, and Homebrew doesn't bring its own compiler the way it half-does on macOS via Xcode CLT. Run brew doctor right after install — it'll tell you if =gcc=/=make=/glibc headers are missing. If the box has no root at all and no build-essential equivalent preinstalled, you're limited to formulae that ship prebuilt bottles for your platform. Check before you plan a whole toolchain around it.

PATH ordering — be deliberate

brew shellenv prepends its prefix to PATH, meaning Homebrew binaries shadow system ones with the same name. Usually what you want for dev tools (newer git, newer python). Usually not what you want for anything security-sensitive — ssh, sudo, su should stay resolving to the system binary. Homebrew doesn't install replacements for those, but it's worth checking which for anything you're unsure about after adding the eval line, rather than assuming.

Why this is worth doing

Same motivation as the GPG/pass setup: one lightweight mechanism, no root, no server, no vendor tie-in — just files under your own home directory that you can tar up, move to the next machine, or delete without asking anyone's permission.
